# 演示脚本（展示网站 / 介绍视频 / 答辩共用）

模型：DeepSeek-V4.1-Flash。所有素材均来自 2026-11-21 的真实运行记录，可按 README 复现。

## 介绍视频分镜（约 3 分钟）

| # | 画面 | 时长 | 内容与台词要点 |
| --- | --- | --- | --- |
| 1 | 终端 / 对照组笔记 | 30s | 问题：只把摘要贴给模型，让它写笔记。展示对照组的编造案例——摘要里根本没有的指标数字被写了出来，quotes 对不上原文（见 eval/results.md 对照组引用命中率）。台词：模型会「一本正经地补数字」。 |
| 2 | 浏览器打开 Harness | 20s | `pnpm dsh web --patch .../plugin/cordis.yml`，打开 `127.0.0.1:3080`，输入「阅读 arXiv:2210.03629，按 paper 技能产出笔记」。 |
| 3 | 工具调用特写 | 40s | 会话视图里的工具卡片依次出现：fetch_arxiv（元数据+摘要）→ list_sections（10 块目录）→ read_section × N → write_note。指出：模型只决定调用谁，工具是确定性代码。 |
| 4 | 打开笔记看原文依据 | 40s | `notes/2210.03629.md`：问题/方法/数据/指标/局限，每节下面是「原文依据」引用块；19 条引用全部逐字命中（校验只合并空白）。 |
| 5 | 退回与重试 | 40s | 展示 LoRA 论文那轮（2106.09685）：第一次 write_note 被退回——编造的 99.9% 指标 + 一条 ∆/Δ 字符级不一致的真实引用；模型按退回清单修正后重交，15 条全部命中。素材：会话记录 + eval/traces/tool-calls.jsonl 的两次 write_note（第一次 ok:false）。 |
| 6 | 评测表收尾 | 30s | eval/results.md：插件组 vs 摘要对照组的引用命中率对比 + 事实核对。台词：引用校验把「看起来对」变成「查得到」。 |

## 现场答辩演示（备选，5 分钟）

1. `pnpm dsh web --patch ...` 起服务（30s）。
2. 对话输入「阅读 arXiv:1706.03762，按 paper 技能产出笔记」（约 1.5 分钟，全程可见 11 步工具轨迹）。
3. 打开 notes/1706.03762.md 展示引用块。
4. 现场演示退回：输入「再读 arXiv:2106.09685，这次先故意在 metrics 里写一个编造数字，展示 write_note 拒绝后再修正提交」。

## 已知边界（如实告知）

- `/paper` 斜杠手势在 web 端对「运行时注册技能」存在 source 校验问题（Harness 0.2.2-rc.5），用自然语言入口或 `dsh headless` 不受影响；详见 README「已知问题」。
- 扫描版 PDF 无文本层会被明确拒绝（不做 OCR）；arXiv 偶发网络抖动，fetch_arxiv 内置 3 次重试，模型也可能自行重试。
- 长文裁剪是按目录选读章节（上下文管理），不是检索式精读。
