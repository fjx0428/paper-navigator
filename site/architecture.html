架构

插件不改 Harness 核心代码：启动时用 cordis.yml 插入一行配置注册工具与技能，模型在 Harness 的 Agent 循环里决定何时调用谁。

一次会话的数据流

用户「阅读 arXiv:2210.03629」
→
paper 技能注入固定阅读顺序与引用规则
→
模型暂定智谱 GLM-5.3-Flash
→
六个工具检索、精读、校验、对照
→
write_note 校验失败退回 · 成功落盘 Markdown

六个工具

工具输入返回
search_arxiv主题词，最多 8 篇编号、标题、作者、摘要。不下载 PDF
fetch_arxivarXiv id标题、作者、摘要；下载 PDF 并抽取章节（内置 3 次网络重试）
list_sectionsarXiv id章节目录（标题、页码范围、词数）
read_section章节序号、max_chars ≤ 12000该节正文（精确按标题行切片）；返回文本进入引用校验语料
write_note笔记 JSON引用校验通过 → 写 Markdown + JSON；否则整体退回并给出逐条错误
compare_notes若干 arXiv id，可省略已落盘笔记的问题 / 方法 / 数据 / 指标 / 局限。不补笔记里没有的数字

笔记结构（字段已冻结）

{
  "arxiv_id": "2210.03629",
  "title": "ReAct: Synergizing Reasoning and Acting in Language Models",
  "problem":     { "text": "中文总结 2-4 句", "quotes": ["逐字英文原句"] },
  "method":      { "text": "…", "quotes": [] },
  "data":        { "text": "…", "quotes": [] },
  "metrics":     [{ "name": "ALFWorld 成功率", "value": "71%", "quote": "含该数字的原句" }],
  "limitations": { "text": "…", "quotes": [] }
}

校验规则：quote 与语料（摘要 + 全部 read_section 返回文本）各自只合并空白字符后，必须逐字包含；长度 ≥ 8 字符。任何一条不通过，整份笔记退回。

插件如何挂进 Harness

# plugin/cordis.yml（patch 叠加在 dsh web 基础组合之上，零核心改动）
- insert:
    - id: paper-navigator
      name: '/绝对路径/plugin/src/index.ts'

插件模块 inject: ['tools', 'skills']，在 apply(ctx) 里注册 6 个工具和 1 个 paper 技能。所有注册挂在 Cordis effect 上，卸载即反注册。

Agent 循环里的角色分工

谁调用模型，谁执行工具？
Harness 的 Driver（packages/core/agent-loop）驱动每一轮 turn：组装提示（工具 schema 注入系统提示）→ 调用模型流式生成 → 从输出中解析 tool-call → 并发执行 → 结果写回会话历史 → 进入下一步，直到模型不再发起调用。模型只输出「调用哪个工具 + 参数」，从不亲自执行任何论文操作；工具是确定性代码，从不调用模型。

上下文裁剪

长论文不整篇进上下文：技能规定「先 list_sections 看目录，再挑与问题/方法/实验/局限相关的 2–4 节，每次 read_section ≤ 12000 字符，正文合计 ≤ 12000 词」。实测 144 页综述（约 40 万字符正文）共选读 13 次、合计 3.6 万字符——见演示页轨迹。
