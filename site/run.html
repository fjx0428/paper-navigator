运行与复现

从零到看到笔记，约 30 分钟（大部分时间在等依赖下载）。以下命令在本机（macOS arm64，Node v26.13.0）验证通过。

步骤

# 0. 准备：Node ≥ 24.9，pnpm 11。两把钥匙都放环境变量，不要写进仓库
npm install -g pnpm@11
export DEEPSEEK_API_KEY="你的 DeepSeek Key"
export ZHIPU_API_KEY="你的智谱 Key"

# 1. Harness 源码（浅克隆足够）
git clone --depth 1 https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness

# 2. 依赖（npmjs 慢时用镜像；中断重跑即可续装）
pnpm install --registry=https://registry.npmmirror.com

# 3. 构建（约 2 分钟）
pnpm run build

# 4. 启动网页并挂载插件（路径换成你的仓库绝对路径）
pnpm dsh web --patch /绝对路径/plugin/cordis.yml
# 打开 http://127.0.0.1:3080 ，对话输入：
#   阅读 arXiv:1706.03762，按 paper 技能产出笔记

关键说明

插件目录为什么有自己的 package.json？
插件源码在本仓库 plugin/（不在 Harness 内）。Harness 根 node_modules 不链接 @deepseek-ai/dsh-tools 等内部包，所以插件目录用 link: 依赖指向本地 Harness 工作区包（vendor/cordis、packages/core/tools、pdfjs-dist）。更换 Harness commit 后，在 plugin/ 里重跑一次 pnpm install。

已知问题

现象原因与规避
web 端 /paper 斜杠手势报 source must be a stringHarness 0.2.2-rc.5 对运行时注册技能的加载校验要求 source 字段。规避：对话直接说「阅读 arXiv:xxx」（技能目录会注入上下文，模型自行调用），或用 dsh headless。
arXiv 偶发 fetch failed本机到 arxiv.org 的 IPv6 路径偶发秒断。插件已优先走 IPv4，并保留 3 次退避；同一篇 PDF 下载成功后缓存在临时目录，复跑不再重下。
扫描版 PDF无文本层会被明确拒绝（本期不做 OCR），换有文本层的论文即可。
